# P19 第一轮：作废（题目出错了）

**日期**：2026-09-10
**协议**：P19-TEAM-ATTITUDE-COUPLED-V1（第一版，已废弃）
**结论**：`INVALIDATED_TASK_DESIGN_ERROR` —— **既不算成功，也不算失败**

## 发生了什么

第一轮冻结配置下，**所有 arm（含全部脚本基线）得分恒为 0.00**，且未写出任何结果文件。

## 两个原因（叠加）

### 原因 A：任务本身无解（几何 + TTL 不匹配）

- 三机被摆成**一条直线**（S–R–K 共线），因此中间节点 R 的"朝 S"与"朝 K"**正好相差 180°**。
- 转向速率 15°/步 → 掉头 180° 需 **12 步**。
- 但情报保鲜期 TTL 只有 **6 步**。
- ⇒ R 永远来不及在保鲜期内把情报转出，K 永远拿不到，**恒 0**。这是**题目无解**，与算法无关：任何策略（含全知最优）都只能得 0。

### 原因 B：脚本基线转向方向写反（代码 bug）

修好 TTL 之后基线**依然**恒 0，进一步定位到 `scripts/p19_train_team_coupled_policy.py: eval_schedule` 中：

```python
err = wrap(desired - env.headings[i])
if err > env.turn * 0.5:
    acts.append(0)     # 错误：err>0 表示"目标在逆时针方向"，应选 +15°，却选了 -15°
```

结果基线每个智能体都朝**远离目标**的方向转，原地发散。这使"脚本基线"这一参照系整体失效。

## 由此暴露的第三个问题：门槛会被"白卷"骗过

原门槛为纯比值形式：

- G1 `learned >= 1.20 × scripted`
- G2 `learned_with_clock >= 1.20 × learned_without_clock`
- G3 `holdout >= 0.80 × train`

当所有量都为 0 时，`0 >= 0` 成立，程序会打印 **PASS**。这是**假奖状**：全零跑分被判定为成功，若写入证据登记册将污染后续判断。因此本轮**主动中止，未落盘任何结果文件**。

## 修正（见 P19-TEAM-ATTITUDE-COUPLED-V2）

1. **折线队形**：链条在 R 处拐弯 100°–140°，使 R 的两次朝向夹角降为 40°–80°（只需转 3–6 步），**有解**。
2. **TTL 6 → 8**：给 S 侧（同时要看目标又要对 R）留出切换余量。
3. **反白卷防呆**：新增 `G0_not_vacuous` 门槛，要求学习策略与脚本基线的得分**严格大于 0**，否则一律判 `P19_INFEASIBLE_OR_VACUOUS`（失败），杜绝"0 ≥ 0"式假通过。
4. 修正 `eval_schedule` 的转向符号。
