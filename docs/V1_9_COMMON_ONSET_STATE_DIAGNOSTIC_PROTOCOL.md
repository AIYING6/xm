# v1.9 Common-Onset-State Secondary Diagnostic Protocol

**Status: `PREREGISTERED_DESIGN_FROZEN__NOT_IMPLEMENTED__D2_NOT_AUTHORIZED`.**

## 1. Purpose and claim boundary

This protocol is a secondary mechanism diagnostic. It does not replace the
end-to-end F2 primary evaluation, does not select a checkpoint, and does not
change the PCRF-R2 architecture, raw-information contract, reward, training
budget, primary comparator, or RMTE estimand.

The end-to-end primary estimand answers whether a complete policy produces
earlier stable task-chain establishment after the scheduled relay failure. It
does not alone establish that an observed difference was caused solely by
post-onset P/C conflict handling. This diagnostic isolates that narrower
question by starting every compared policy from the same simulator state at
relay-failure onset.

## 2. Frozen terminology and hypothesis

| Term | Frozen meaning |
|---|---|
| **onset state** | A complete, restorable simulator state immediately before the first transition for which the relay failure is active at step 40. |
| **state-bank behaviour** | A non-learning, method-independent pre-generated discrete action sequence; it is never a PCRF-R2, single-R2, or non-graph policy. |
| **common onset** | The byte/hash-verified same onset state, including legal packet/cache state, is restored separately for every method/checkpoint evaluation. |
| **post-onset effect** | A difference after restoring the same onset state; it remains a secondary diagnostic, not a substitute for the end-to-end primary effect. |

The diagnostic hypothesis is deliberately conditional: if PCRF-R2 has a
favorable primary end-to-end F2 result, it may also have earlier post-onset
establishment than source-aware single-R2 when both begin from the same legal
onset state. Failure of this diagnostic removes the pure post-onset mechanism
interpretation; it does not retroactively negate an independently supported
end-to-end result.

## 3. Frozen state-bank generation

The state bank will use the exact nominal R2 environment configuration:

- strict target sensing and agent-target information bottleneck;
- communication dropout 0.30, delay 2, radar dropout 0.10;
- failed blue agent 1, failure onset 40, failure duration 80;
- `K=4`, minimum success step 80, fixed horizon 260;
- `max_target_message_age_steps=80`, minimum target confidence 0.20; and
- no OOD geometry, communication, maneuver, reward, or architecture setting.

Candidate simulator seeds are the ordered integers `60000` through `60599`.
For candidate seed `s`, the complete pre-onset action sequence is generated by
`numpy.random.Generator(numpy.random.PCG64(80000 + s))` and sampled uniformly
from the frozen 27-action table for all three blue vehicles. The action
sequence, candidate seed, RNG algorithm/version, and environment configuration
digest are written before evaluating any compared checkpoint.

An onset state is eligible only if it reaches the pre-failure boundary without
a terminal outcome and has no stable task-chain establishment before onset.
The bank comprises the first **300 eligible** candidates in ascending candidate
seed order. If fewer than 300 candidates are eligible, the diagnostic is
`BLOCKED`; no adaptive replacement, action-policy change, or seed selection is
permitted. Candidate eligibility and the selected 300 IDs must be recorded even
if the diagnostic is never executed.

## 4. Required snapshot and restoration contract

Each saved onset state must include every dynamic variable that can affect a
future legal observation or transition: simulator step/time; all blue and
target kinematics and energy; target-policy state; sensing history; relay
failure state; attack/chain hold state; communication adjacency and message
ages; delivered sender-status packets; delivered target caches with generation,
delivery, path, age, confidence and validity fields; pending packets and their
delivery times; all environment RNG states; and any action/history state used
by environment feature construction.

Restoration must produce, before a new post-onset action is selected:

1. identical state-bank ID and immutable state SHA256 for every evaluated
   method/checkpoint;
2. equal failure onset and remaining horizon;
3. identical simulator target/UAV/packet/cache state; and
4. identical recipient-specific R2 P/C/context tensors for the same receiver.

Snapshots may contain simulator truth only as stored environment state. They
may not be passed as actor inputs. The restored actor inputs must again be
constructed through the canonical recipient-specific P/C pipeline; the
actor-boundary and source-provenance tests remain mandatory on the execution
commit. PCRF-R2, single-R2, and matched-information non-graph-R2 receive no
method-specific message, cache, history, hidden state, or privileged field.

The current actors are feed-forward. If a future candidate introduces a
recurrent/latent actor state, this protocol is invalid until the author freezes
a method-neutral treatment of that state; it may not be silently zeroed or
copied across methods.

## 5. Fixed evaluation matrix and endpoints

For every selected formal F1 checkpoint in the separately frozen formal matrix,
evaluate every one of the same 300 onset states. The same state-bank IDs are
paired across PCRF-R2, single-R2, and matched-information non-graph-R2. This
diagnostic does not determine the F1 seed set, selected checkpoints, validation
rule, or F2 episode bank.

At post-onset horizons `tau=80` and `tau=220`, record exactly the repaired
complete-follow-up outcomes:

1. `RMTE80` and `RMTE220` from onset to first `K=4` stable establishment;
2. establishment incidence by each horizon;
3. terminal-failure incidence before establishment by each horizon; and
4. active-but-unestablished incidence at each horizon.

Terminal collision, constraint violation, or another audited irreversible
mission-terminal outcome contributes the horizon to RMTE, exactly as specified
in `V1_9_P0A_TERMINAL_OUTCOME_ESTIMAND_FREEZE.md`. No Kaplan--Meier treatment
of terminal failure as ordinary censoring is permitted.

The primary secondary-diagnostic contrast is paired
`Delta RMTE80 = RMTE80_PCRF-R2 - RMTE80_single-R2`; negative favors PCRF-R2.
The matched-information non-graph comparison is reported secondary. All
outcome components, every method, and every predeclared contrast are reported;
there is no cell selection by observed benefit.

## 6. Frozen statistical analysis

The analysis uses the same hierarchical paired bootstrap structure as the
formal comparison: resample formal training seeds, then resample the 300 shared
onset-state IDs within seed. Report the paired bootstrap interval for
`Delta RMTE80`, the paired difference in establishment incidence, and the
terminal-failure incidence difference. The estimator, bootstrap resample count,
practical margin, and decision thresholds are inherited unchanged from the
separately frozen F1/F2 statistical protocol; this diagnostic may not create a
new selector or retune any threshold after results are seen.

## 7. Interpretation rules frozen before results

| End-to-end F2 | Common-onset diagnostic | Allowed statement |
|---|---|---|
| supports PCRF-R2 | supports PCRF-R2 | End-to-end advantage is consistent with, and the secondary diagnostic supports, a post-onset PCRF mechanism under the specified state bank. |
| supports PCRF-R2 | does not support PCRF-R2 | Retain only the end-to-end performance conclusion; do not claim pure post-onset conflict-handling superiority. |
| does not support PCRF-R2 | either result | Withdraw the corresponding PCRF-R2 superiority claim. |

No outcome permits an architecture change, an F2 primary-protocol change, a
budget/seed change, or a post-hoc state-bank modification.

## 8. Implementation gate and prohibited work

This document authorizes design freeze only. Before any execution, a separate
implementation authorization must require deterministic snapshot/restore
round-trip tests, state and R2-input hash parity tests, cache/packet provenance
tests after restore, and a method-independent replay test. The work may not
begin D2, F1, F2, OOD, a performance comparison, or an architecture revision.
