# V5 组合式服务信封交接任务：开发合同

## 决策

V4 已经证明二元中继承诺接口可被普通 MAPPO 学会，但三个独立 seed 都把公开服务类别直接映射为确定性动作。因此 V4 不能检验“消息新鲜度、路线可达性和交接价值”的关系机制。V5 不调节 V4 的成功阈值，也不把 V4 结果并入后续统计；它以新的任务合同替换这一条静态分类捷径。

## 固定不变项

- 原有三架异构 UAV、3DOF 动力学、感知、消息传输、碰撞与约束处理；
- 二元中继宏动作：`retain_current` 与 `reconstruct_future`，以及 8 物理步 option；
- 仅中继宏动作进入 PPO actor/KL/熵，critic 仍接收全体 UAV 状态；
- actor 不读取目标真值、未来目标机动、critic 特征或评估条件；
- PPO、奖励尺度、低层闭环控制和训练预算在同一 V5 对照内保持一致。

## 唯一任务重构

每个 episode 向 actor 发布两个**公共服务信封**，而非 `current_authorization` / `postbranch_refresh` 的 one-hot 类别：

\[
e_r=(\tau_r, a_r, h_r, \rho_r), \qquad r\in\{\text{current},\text{future}\},
\]

其中 \(\tau_r\) 是剩余服务时限，\(a_r\) 是已送达请求消息的年龄，\(h_r\) 是所需合法服务保持长度，\(\rho_r\) 是公开路线支持状态（由中继到相应服务走廊的可见相对位置和链路条件组成）。信封中的量全部来自 actor 已见的公共命令或本地消息/链路状态；不引入隐藏目标状态。

环境在每个 profile 中以固定、可审计的规则把信封价值映射为所需服务路线。最小 profile 集合必须包含四个组合：两个以当前服务为最优、两个以未来服务为最优；每类各包含不同的时限/消息年龄组合。任何单一字段都不能恒等决定路线，只有合法信封关系共同确定两条路线的相对价值。

## V5 的零训练 G0

G0 不是学习测试。对每个 profile、至少六个物理随机 seed，运行两个同一低层控制器：始终保持当前、始终重构未来。通过条件为：

1. 每个 profile 的最优控制器在预设成功定义下成功；
2. 另一控制器失败；
3. 两类最优动作都至少出现两个 profile；
4. 所有请求字段、路线坐标、消息年龄和 link 状态均来自 actor 可见字段审计；
5. 脚本报告包含 profile、信封、选择、服务轨迹、故障/碰撞与终局，不能只报告平均成功率。

若任一 profile 无法形成方向相反的可达终局，先修复该 profile 的服务时限/走廊几何，不启动学习。

### G0 实测结果（2026-09-14）

使用六个物理随机 seed，对每一个 profile 分别执行固定 `retain_current` 与固定 `reconstruct_future` 中继控制。`current_compact` 与 `current_delayed` 中，保留路线成功率均为 1.00、重构路线为 0.00；`future_fresh` 与 `future_durable` 中，保留路线为 0.00、重构路线为 0.833。四个画像均形成非零且方向相反的控制差，因而零训练门禁得到 `V5_G0_COMPOSITIONAL_DECISION_SWITCH_PASS`。

该检验仅证明任务中存在可达、可见且影响终局的选择反转；它不证明学习算法能从服务信封学习该选择，也不构成论文性能结果。

## V5 的 G2

容量匹配、无图、无候选模块的 MLP MAPPO 在混合四 profile 训练分布上运行三个开发 seed。每个 seed 在每 profile 的固定 endpoint tape 上分别报告成功、超时、碰撞、两类承诺比例和信封字段。G2 的目标不是让基线失败，而是证明它可学习、但尚存在组合化决策余地：

- 不能总体全零；
- 不能所有 profile 近乎确定性满分；
- 不能退化成只由一项信封字段决定动作；
- 必须对 current-optimal 与 future-optimal profile 都产生非零成功。

具体非饱和区间、种子和 endpoint tape 必须在 G0 通过后、首次 G2 训练前一次性冻结，不得看见 G2 结果后修改。

### 已冻结的首次 G2 执行合同

- 训练 seed：`82341, 82342, 82343`；每 seed 64 updates、4 个并行环境、每 rollout 64 个中继宏决策，合计每 seed 16,384 个宏决策 / 131,072 个物理步；
- 训练画像：`balanced_v5`，四个并行环境按固定索引对四个具体 profile 一一、等频分配；每个实际 episode 均保留其具体 profile，不把“混合”作为不可审计类别；
- 固定 endpoint：每 seed × profile 60 回合，使用未参与训练的固定 evaluation seed 带；输出成功、超时、碰撞、终局服务进度与中继 `reconstruct_future` 比例；
- 通过条件：对每一个 profile，至少 2/3 训练 seed 的成功率落入 `[0.10, 0.90]`；同时 future-required profile 相对 current-required profile 的平均重构比例差至少为 `0.15`。该上限用于排除再次出现的近满分静态映射，下限用于排除不可学习任务。

上述 G2 仅判断任务和普通对照是否进入可研究区间；它不构成候选方法证据，也不得在结果看到后回调阈值。

## G3--G4 候选机制

仅在 V5 G2 通过后实现**服务信封关系价值策略**：对两条已存在候选服务关系分别由 \((\tau,a,h,\rho)\) 计算可解释价值，价值差条件化中继的二元动作分布。主 MLP 对照参数量匹配；消融仅随机置换“信封关系 \(\rightarrow\) 路线价值”的语义对应，其他输入、参数、奖励、PPO、预算、seed 和 endpoint tape 均不变。

G3 需在 2--3 个开发 seed 同时显示：不同的承诺行为遥测、相对 MLP 的任务或可靠性收益、以及不使用隐藏信息。G4 需显示语义打乱导致性能或关键行为退化。二者通过后才冻结正式 5 seed 以上实验。
