# DRTP 中文投稿稿 V3：通信拓扑退化问题重构说明

## 核心论点

本文研究的不是“怎样把故障条件采样得更漂亮”，而是：**在通信拓扑退化改变可获得信息与角色协同约束时，如何通过训练阶段的拓扑语义化暴露塑造，提升多智能体策略在冻结故障接口内的鲁棒协同表现。**

DRTP 是这一问题的训练侧解法：它不改 actor、critic、PPO、奖励、观测、动作接口或环境转移；仅在 reset 阶段、于预定义拓扑故障组之间自适应分配训练暴露。

## 术语账本

| 术语 | 本文固定含义 | 不应写成 |
|---|---|---|
| 通信拓扑退化 | 节点/链路失效或其时序引起的通信图与信息路径变化 | 一般噪声或任意环境扰动 |
| 鲁棒协同 | 在冻结拓扑故障评估协议内维持的 cohort-level 协同表现 | 对任意故障的保证 |
| 拓扑语义化鲁棒性塑造 | 以预定义故障组、名义参考和受约束概率更新塑造训练经验 | 部署期通信修复模块 |
| UTR | 固定名义质量、非名义组均匀采样的匹配对照 | 弱基线 |
| PLR-style | 通用 priority 驱动的匹配外部比较器 | 被 DRTP 全面击败的方法 |
| cohort | 五个独立训练 seed 构成的一批重复 | 可随意合并为确认性 n=10 |
| fixed endpoint | 训练期间不可访问的冻结终点评估 | 可按中途表现挑选的评估 |

## 实验组织

- **RQ1：** 比较 UTR 与 DRTP 的 A/B independent cohort 固定终点；主看扰动回报、lower tail、timeout 与 collision 的分别报告。
- **RQ2：** 报告冻结结构 OOD 与参数 shift；仅宣称协议覆盖范围内的泛化。
- **RQ3：** 以匹配 PLR-style 检验“拓扑语义”是否可与一般 priority 区分；结论写为竞争性、cohort 依赖的取舍。
- **RQ4：** 待 6-UAV UTR/DRTP 的正式训练和固定终点评估完成后，补充跨尺度证据。

## 不新增长训练即可完成的机制统计

当前已从**冻结 sampler telemetry 与固定 endpoint 条件汇总**导入 q 轨迹、实际暴露、最终记录困难度和条件级终点表现。完成 6-UAV 后，在取得精确图定义的前提下，优先补齐下列只读图统计：

1. 每个条件的边断裂数、可达性/连通性、平均最短路径变化与图退化程度；
2. 条件描述符与名义相对困难度的 cohort 分层关联；
3. 困难度与实际 exposure share 的 cohort 分层关联；
4. 条件级终点回报、success、timeout、collision 的对齐展示。

这是一项解释性、描述性分析：不改算法、不增加新训练、不挑 checkpoint，也不将相关性写成策略内部的强因果证明。

## 审稿风险与处理

1. **“只是采样技巧。”** 用图1–2与问题定义先确立通信图改变信息结构；用 PLR-style 直接回答其与一般 priority 的关系。
2. **“机制因果不足。”** 将拓扑统计限定为冻结日志上的机制一致性分析；避免写成已识别唯一因果机制。
3. **“PLR 在 B 回报更高。”** 不做全面排名。准确报告：A 中 DRTP 的回报/lower tail/timeout 更有利，B 中 PLR-style 回报与离散度更有利，而 DRTP timeout 更低。
4. **“跨尺度证据不足。”** 6-UAV 未完成前不得投稿；完成后按既定 RQ4 表与图填入，不重构全文。
5. **“计算代价未报。”** 在最终训练日志上补 DRTP/UTR 每 1M 环境步壁钟时间、显存与 sampler 更新开销，保持相同硬件与配置。
6. **“仿真不等于部署。”** 限定为仿真与冻结通信拓扑退化协议，不使用实飞、通用安全或保证性表述。
