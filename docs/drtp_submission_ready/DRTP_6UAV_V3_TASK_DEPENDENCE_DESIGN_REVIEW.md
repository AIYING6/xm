# 6-UAV V3：任务依赖设计审查

**状态：** 设计审查；未创建训练队列，未授权新的 10M 实验。

## 1. 审查结论

V2 的失效不是 fault injection timing 的单点问题。`fault_step=3` 已经确保
六个非名义组在任务结束前真正改变活动边；但所有故障端点仍然饱和。零训练筛查进一步表明，
仅延长终端路线或缩短缓存有效期会把冻结策略从“全部成功”直接推向“名义任务也失败”，
而不能形成名义可解、故障可分的压力区间。

其结构原因是：当前 relay 是自动转发器，relay action 恒为唯一的 PASS/IDLE；一个
故障边或一个 relay 的失效通常仍保留替代路径，并由环境自动完成转发。终端只需要获得
足以推进的消息缓存。因此，策略没有必须在故障后重新分配有限通信资源的决策问题。

**结论：V2 不应再通过改 fault timing、路线长度或超时阈值反复训练。**

## 2. V3 所需的任务性质

一个有资格承载“拓扑退化下协同鲁棒训练”比较的扩展任务，至少需要同时满足：

1. **持续支持：** 完成目标需要故障后持续获得合法的新鲜信息，而不是在故障前收到一次
   缓存后即可完成。
2. **有限而可控的中继资源：** 转发能力或消息时隙受限，且其分配由 relay 策略决定，
   不能由环境替策略自动选路。
3. **可恢复的部分退化：** 故障应降低可用路径/容量，但不应把所有任务都变成绝对不可达。
4. **同一决策接口下的对照：** UTR 与 DRTP 使用完全相同的 actor、critic、PPO、奖励、
   观测、动作、预算和故障支持；正式比较唯一改变 reset 阶段的训练组暴露分配。
5. **先可解、后比较：** 名义任务和至少一部分故障任务必须先由 UTR 学到非退化策略，
   才能讨论 DRTP 的训练暴露是否带来收益。

## 3. 推荐的最小 V3 任务改动

V3 应使用一个**独立环境适配器**，而不是改写 V2 环境或回写既有结果。最小的、
可解释的改变是将 relay 从自动转发改为“每个时隙选择一个可转发 objective 的受限转发者”：

- relay 动作：`idle / forward objective-0 / forward objective-1`；
- 每个 relay 每时隙最多转发一个 scout packet；
- terminal 的推进要求当前时隙或规定极短有效期内的合法支持；
- 两个 relay 在名义拓扑下可并行支持两个 terminal；部分拓扑退化后仍存在合法替代路径，
  但需要 scout、relay 与 terminal 在有限容量下协调选择服务对象；
- 目标价值、奖励、角色数量和故障族在 V3 协议冻结前统一预先定义，不能依据 DRTP 结果回调。

这不是对 DRTP 的修改，也不是把场景设置成保证 DRTP 获胜；它只是使“通信拓扑改变信息和
协同资源分配”成为策略必须面对的真实任务变量。

## 4. 不采用的伪修复

| 伪修复 | 不采用原因 |
| --- | --- |
| 再提前 fault step | 只保证故障发生，不能产生持续协同压力。 |
| 只拉长 terminal 路径 | 筛查已显示会同时破坏名义可解性。 |
| 设置完全断联/无路由 | 变成不可恢复的物理不可达，训练分配无法解决。 |
| 自动限流但 relay 无动作 | 把关键资源分配继续交给环境，策略无法体现拓扑适应。 |
| 根据 DRTP 中间表现再调难度 | 破坏正式比较的可解释性，禁止。 |

## 5. 分阶段证据门槛

1. **Q0 语义校准（零训练）：** 验证每个故障组的注入时序、活跃边、可达性、relay 时隙
   容量和新鲜信息门槛；确认名义有两条并行服务链，退化组降低但不清零可服务能力。
2. **P1 UTR 可学习性资格试验：** 仅训练 UTR 的小规模预注册 pilot；确认名义可学习、
   非名义条件既不饱和也不全部失败。该阶段不得运行 DRTP 或比较优劣。
3. **冻结协议：** 仅在 P1 满足预设资格门槛后，冻结环境 hash、种子、预算、故障组和
   endpoint tape。
4. **正式 UTR–DRTP 比较：** 在冻结协议下训练；所有性能结论仅属于 V3 任务，不能回写
   到 V2 或 3-UAV 的正式结论。

## 6. 论文处理

在 V3 得到有效、冻结的比较之前，主稿不应声称已完成 6-UAV cross-scale validation。
V2 可以在补充材料或工程审计中保留为一次有效故障注入、但不可判别的任务设计发现；它不应
作为支持或反驳 DRTP 性能的证据。
