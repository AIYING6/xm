# 多威胁双能力防御：G0 合同

该环境回应上一版“单动能执行者”无法并行应对双威胁的结构缺口。攻击 UAV 通过已有攻击窗口实施动能中和；侦察 UAV 可在合法观测、距离、通信路径与连续保持均满足时，对一架红方施加持续时间有限的非动能干扰。干扰不消灭目标，也不能同时作用于两架目标；它仅降低被干扰目标的推进速度，为动能拦截争取有限时窗。

因此冲突来自真实的能力容量：同一时刻只能压制一架威胁，而动能 UAV 也只能建立一条攻击链。蓝方仍只输出原始 3DOF 飞行动作，未获得“选择压制目标”的宏动作或额外观测标签。

当前状态仅为 G0。G1 必须验证三类透明策略——动能优先、压制后拦截、错误目标压制——在不同几何格点具有非退化终点取舍；否则不训练、不提出算法。

首轮 G1 显示所有透明控制器在全部上下文中均实现防御成功、零资产失守。双能力构造确实提供了并行行动，但当前时间与距离尺度使任何简单控制器都能完成任务，因而终点饱和。该版本不进入 G2；不能把回报细节差异包装成机制性能收益。

后续不再逐点猜测参数。冻结的校准格点将系统扫描分支时机、资产纵深和蓝方展开度，并以预先声明的终点规则选择候选区域：并行压制—拦截必须优于纯动能优先，同时自身不能饱和。若格点没有候选，任务线停止；若有候选，仍须以独立 G1 和 plain-MAPPO G2 验证后才能设计方法。

校准实施中发现多威胁封装遗漏了基础 3DOF 环境已有的连续攻击保持约束，错误地把单步攻击窗口视为即时中和。该实现缺口已修复：两架威胁各自需要满足独立的连续攻击保持。此前相图仅用于发现该缺口，不作为任务难度或方法证据；修复后使用同一预注册格点重新校准。

v1 相图还显示其轴选取不足：资产纵深与蓝方展开度不能直接刻画单攻击 UAV 的串行转场容量。因此 v2 固定纵深，系统扫描红方横向分离、资产横向分离与分支时机。这三项共同决定两个威胁是否真正时间重叠；v2 的所有单元均报告，不以事后单元替代预注册规则。

v2 仅有一个边界单元显示并行压制—拦截能够在终点上超过两个对照，但其 6/6 成功仍属饱和。v3 因而在该边界附近预注册局部格点；只有并行方案在 2–5/6 初值中成功且相对纯动能优先至少多成功 2/6 时，才能产生待独立复核的非饱和候选。

静态 v3 格点进一步表明原“seed”未改变物理场景，不能估计可靠性。v4 固定三个已报告的机制边界格点，并冻结红方接近中心、速度与分支时机的有界场景分布。不同 seed 现在对应同一分布下的不同物理实例，而非重复同一轨迹。
