# P20：基于 DRTP 的强二区升级路线——拓扑条件恢复与暴露塑造

## 1. 决策

`P20_CONTRACT_FROZEN / STAGE-0 NOT YET EXECUTED / NO TRAINING`

P20 不试图把既有 DRTP 重新命名为新算法，也不将既有 A/B、held-out 或 PLR 结果追认为 P20 的性能证据。它将 DRTP 限定为训练期的**暴露塑造层**，并增加一个必须独立验证的执行期研究对象：拓扑退化发生后的协同恢复选项选择。

## 2. 为什么这是对 DRTP 的升级而不是拼接

原 DRTP 的唯一干预是 reset 阶段各故障组的训练概率。其正式证据支持：在两个冻结 10M cohort 中，DRTP 相对 UTR 观察到重复的 perturbed-return cohort 平均增益；但这不能解释执行中团队如何恢复，也不能成为完整恢复算法的证据。

P20 的因果链改为：

`动态拓扑退化 → 合法局部症状 → 恢复选项选择 → 支撑路径恢复/任务连续性 → DRTP 训练暴露塑造`

只有这条链中的恢复选项在统一物理任务下具有不可替代的决策区域，DRTP 才有资格作为训练层与恢复层共同构成一个新算法。

## 3. 新任务语义

团队由 scout、relay 和 terminal 构成，完成两个需要新鲜合法任务支撑的顺序目标。故障必须发生在初始任务进展之后、两个目标完成之前。恢复动作不是 evaluator 提供的标签，而是会消耗实际时间和服务能力的物理操作：继续执行、继电重定位、角色重分配或安全回退。

角色、目标、动作以及消息年龄的观测必须保持可部署性。故障标签、全局图、未来链路、反事实 option value 均被禁止进入 actor。

## 4. 与已关闭支线的边界

| 既有支线 | 为什么不可直接复用 | P20 的区别 |
|---|---|---|
| ACFID | 宏观 fault→recovery-action 资格任务，且真实 V31 环境缺少足够复合决策缺口 | P20 是连续任务中的故障后控制与任务连续性，不以 fault registry 或组合预测为核心 |
| 6-UAV v2 | 故障注入有效但 UTR 全端点天花板，不能区分方法 | P20 先以动态范围门排除天花板或全局崩溃 |
| DRTP 主文 | 训练采样改变、无执行期恢复方法 | P20 的主创新是恢复决策；DRTP 只是一项可消融的训练层 |

## 5. 2×2 因果设计

| 方法 | 执行期恢复选项层 | 训练期 DRTP 暴露层 | 回答的问题 |
|---|---:|---:|---|
| UTR-direct | 否 | 否 | 标准基线 |
| DRTP-direct | 否 | 是 | 原 DRTP 的训练期贡献 |
| UTR-recovery | 是 | 否 | 恢复层单独是否有效 |
| DRTP-recovery | 是 | 是 | 训练—执行协同是否有增量 |

四方法共享 3DOF 动力学、PPO、网络容量、奖励、执行信息、预算、名义训练暴露、故障支持与固定评估带。训练 seed 是唯一独立统计单位。

## 6. 训练前停止门

P20 首先只做同一物理任务下的脚本策略/动态规划审计。至少三种恢复选项必须在冻结上下文网格中各自拥有非平凡最优区域；任一固定选项不得统治；逐状态 oracle 相对最佳固定选项必须保留任务价值余量；并且故障后仍需存在非饱和、非全局失败的自然目标进展。

任何一项失败，P20 停止而不训练网络。通过后也只授权 3-seed UTR-direct 可学习性 pilot；基线不过或饱和，同样不训练候选方法。

## 7. 可发表主张的上限

若后续所有门和正式 2×2 实验通过，P20 可以主张：在本文评估的动态拓扑退化任务中，拓扑条件恢复选项与训练期暴露塑造共同改善任务连续性或其可靠性权衡。

不得主张：普适通信恢复、任意拓扑下最优、每个 seed 改善、硬件实飞有效或安全保证。
