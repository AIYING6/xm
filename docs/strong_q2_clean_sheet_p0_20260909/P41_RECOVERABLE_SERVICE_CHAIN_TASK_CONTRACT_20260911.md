# P41: 动态可恢复服务链协同任务合同（零训练设计版）

## 状态

**TASK RECONSTRUCTION ONLY — no learning method is authorized.**

本合同的目的不是把既有 DRTP 故障组随机化换成更复杂的参数，也不是为任何既定算法制造优势。它先建立一个可被简单基线否证、具有真实时序决策张力的非武器化 UAV 协同任务；只有任务通过审计后，才允许从其可观测缺口推导方法。

## 1. 应用语义

面向灾后巡检与应急服务：异构 UAV 团队需要在有限时间内完成多个动态出现的基础设施/救援服务请求。每个请求必须经过**发现/确认 → 可靠传递 → 现场服务**的服务链；通信或中继退化会改变信息到达和可行动的时间，而不会赋予策略隐藏信息。

该任务不涉及目标识别、打击、攻击分配或自主伤害决策。

## 2. 最小角色与动作后果

| 角色 | 决策 | 稀缺资源 | 对后续阶段的后果 |
| --- | --- | --- | --- |
| 巡检 UAV | 选择巡检哪个候选区域，或移动至可见点 | 传感时隙、航程、重访时间 | 决定哪些请求可被确认及信息新鲜度 |
| 中继 UAV | 选择保持、重定位或服务哪条信息链 | 空中位置、链路覆盖、重构时间 | 改变可用消息路径，迁移期间会失去当前覆盖 |
| 服务 UAV | 选择接受、延后或撤回一个已确认请求 | 服务时窗、行程、一次性承诺容量 | 承诺后不能无代价切换；错过时窗会产生可观测损失 |

所有角色只接收合法的本地观测、时间戳消息及其可达链路；全局请求真值仅供中心化 critic 和审计使用，绝不进入执行期 actor 输入。

## 3. 每回合的多阶段结构

1. **启动阶段**：存在若干低优先级可巡检区域；团队选择初始覆盖与链路布局。
2. **演化阶段**：服务请求按冻结随机 tape 出现、升级或过期；已确认请求的价值会随时间下降。
3. **拓扑退化阶段**：在任务已经启动后出现受支持的链路/节点退化；中继可通过有限移动或重定向恢复部分、但非全部服务链。
4. **收口阶段**：团队在相互冲突的截止期内完成、延后或放弃请求；回合以成功服务、不可恢复过期或总时限结束。

这要求策略在保持当前服务、重构信息链和追逐未来高价值请求之间作真实权衡。故障不是静态初始条件，也不能仅靠预设时间表绕开。

## 4. 奖励与指标：避免稀疏信用和单一分数

奖励只由可审计事件组成：合法确认、有效消息传递、开始服务、按时完成、过期、碰撞/越界及无效重构成本。必须记录分项，且不把总回报自动解释为安全性。

预注册端点：

- 按时完成的加权服务价值（主任务端点）；
- 确认至服务的延迟及过期率；
- 有效信息链恢复率与恢复时间；
- 空闲/重复服务率；
- 碰撞、越界和能耗代理；
- 条件化下尾表现（训练 seed 为独立单位）。

## 5. 任务必须主动排除的伪张力

下列任一情况均使任务停止，不进入算法训练：

1. 固定角色—区域分工在不同 tape 上接近最优；
2. 最近请求、最高价值、最早截止期或静态最短路径规则之一接近预注册 oracle；
3. 任何拓扑退化对决策与端点均无实质影响；
4. 所有故障条件全局超时/失败，或名义条件不可学习；
5. 通过向 actor 泄露未来请求、全局拓扑、隐藏优先级或 oracle 分配才能产生优势；
6. 仅改变奖励权重或截止期即可翻转“机制优势”。

## 6. 必须先实现的非学习规则基线

1. 静态分工：固定区域与中继位置。
2. 贪心价值：选择当前已知价值最高的可服务请求。
3. 最早截止期：选择剩余时窗最短的合法请求。
4. 拓扑贪心：在当前局部可见图上优先最大化即时可达性。
5. 特权上界：可访问全局状态但遵守同一动力学与动作约束的规划/搜索上界。

规则基线必须使用与学习策略完全相同的执行期信息边界；特权上界单独标注，不能作为公平主基线。

## 7. 预训练任务有效性门槛

| 门槛 | 通过条件 | 失败动作 |
| --- | --- | --- |
| T1 信息合法性 | actor、critic、审计字段及 tape 的信息边界由自动测试确认 | 停止并修正环境，不调参数 |
| T2 动态决策性 | 至少两种合法规则策略在不同 tape/退化条件下交叉占优，且无固定规则接近上界 | 停止：任务退化为固定规则 |
| T3 可恢复性 | 退化后存在合法但有成本的链路重构，且其完成率、延迟和服务结果会改变 | 停止：故障没有决策后果 |
| T4 可学习带 | 短 UTR pilot 在名义场景超过规则下界，故障场景有下降但非全局崩溃 | 停止：过难或过易 |
| T5 机制空间 | 规则失败轨迹显示可区分的部分信息/机会成本错误，而非只缺训练步数 | 才允许提出算法候选 |

T1--T3 是零训练/规则审计；T4 是小规模 UTR 学习性试验；T5 是方法立项前的诊断，而非事后解释。

## 9. 通过后的方法推导原则

只有当 T5 指出某类可重复的**信息—承诺—恢复**决策错误时，方法才可针对该错误建立。候选方法的唯一干预点、对照、消融、遥测和失败判据必须在训练前一并冻结。
