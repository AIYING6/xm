# P3A 投稿级任务设计：未确认通信下的闭环任务承诺

## 研究对象

P3 不再把通信失败建模为一次二元标签，也不把 `commit/defer/fallback` 的结果直接查表赋值。三架异构 UAV 分别承担侦察、转发与执行角色。侦察机生成带版本号的任务走廊计划，经中继发送给执行机；计划消息与确认消息可能丢失、延迟或过期。各智能体只能看到本地发送、接收和消息年龄，不能看到全局交付真值。

任务问题是：当侦察机与执行机可能持有不同版本的联合计划时，策略应在有限攻击窗口内继续联合承诺、延迟决策，还是切换为收益较低但可独立完成的保守任务。

## 为什么不再是两阶段分类器

一个 episode 包含任务发现、计划发送、私有接收、接近、承诺窗口、联合执行和恢复/降级阶段。策略在八个决策时刻重复输出任务模式及连续转向/爬升制导；固定控制器只保留边界保护和加速度。因此任务成功、单边进入、恢复、超时、碰撞、约束违规和能耗都必须从 3DOF 闭环轨迹产生。

P2 中由标签直接赋值的任务价值只用于最小可学习性筛选，不进入投稿级证据。

## 通信条件

训练条件冻结覆盖：正常双向确认、计划已达但 ACK 丢失、计划丢失、计划延迟、计划版本过期。公开链路上下文和任务紧迫度构成额外因子。`delayed + stale` 与 `ACK lost + stale` 的组合在设计阶段指定为 compositional held-out；它们在未来只能按预先声明的探索性泛化证据解释。

## 可识别消融

正式机制矩阵为二因子设计：是否估计信息区间 × 是否按区间最坏任务价值决策。四个容量匹配方法分别是直接循环 MAPPO、点信念鲁棒承诺、区间直接策略和完整信息集承诺。delivery-truth oracle 只作为信息上界，不属于公平主比较。

该矩阵避免把所有结构归纳偏置同时塞进一个候选与普通 GRU 对比，从而分别识别“区间表示”和“鲁棒任务价值”是否提供增量作用。

## Q0 之前的边界

P3A 只冻结设计，不证明代码实现已经符合设计。下一步只能实现环境并运行零训练 Q0。只有所有通信条件可达、私有信息关系准确、闭环脚本覆盖成功/单边失败/恢复、常数模式不支配、任务不饱和且运行状态可精确恢复，才允许讨论训练预算。
