# P10 推荐主线：受计算时延约束的多无人机决策有效性契约

**状态：** `DVC_PROVISIONAL_TOPIC_ONLY`  
**训练授权：** 否  
**暂定简称：** DVC-MARL（Decision-Validity-Contract MARL）  
**暂定题目：** 面向随机计算时延的多无人机协同决策有效性契约学习

## 1. 推荐判断

推荐研究“决策与实时执行之间的闭环失配”，但不把论文做成普通的 delay-aware MAPPO、AoI 优化或网络调度。真正的科学问题是：

> 多智能体策略基于状态快照开始推理，但物理系统在推理期间继续演化；当动作计算完成时，原决策可能已经失效。如何让策略同时给出动作、有效域和回退行为，使异步完成的团队决策只有在当前状态仍满足执行契约时才被采用？

这里的主要失配不是训练中的 reward delay，也不是单纯通信包龄，而是

\[
\text{observation time} \neq \text{decision completion time} \neq \text{actuation time}.
\]

标准零时延仿真默认三者重合；直接在观测中加入 delay 只能告诉策略“延迟了多久”，不能判断动作基于的旧状态是否仍位于该动作的有效区域。

## 2. 候选决策对象

对智能体 \(i\)，策略在快照 \(o_i(t_s)\) 上输出三元组

\[
(a_i,\;\mathcal V_i,\;a_i^{\mathrm{fb}}),
\]

其中 \(a_i\) 是计划动作，\(\mathcal V_i\) 是该动作允许执行的状态—时间有效域，\(a_i^{\mathrm{fb}}\) 是契约失效后的有限时安全/任务降级动作。推理在 \(t_c=t_s+\tau_i\) 完成后，运行时使用合法可得的当前局部状态 \(o_i(t_c)\) 判定：

\[
u_i(t_c)=
\begin{cases}
a_i, & (o_i(t_c),\tau_i)\in\mathcal V_i,\\
a_i^{\mathrm{fb}}, & \text{otherwise}.
\end{cases}
\]

候选方法的研究对象是**决策有效期及其运行时接受语义**。推理时间越长并不必然导致动作无效：系统状态变化小或动作对变化不敏感时，旧决策仍可接受；短时延也不必然安全，例如临近碰撞边界时。

## 3. 与已知拥挤方向的边界

| 方向 | 已有研究通常优化什么 | DVC 必须额外做到什么 |
|---|---|---|
| Delay-aware RL/MARL | 将固定或随机 delay 纳入状态/模型 | 对每个动作学习可核验的状态—时间有效域，并改变运行时接受/回退语义 |
| AoI-aware UAV MARL | 优化数据新鲜度、调度、轨迹或通信资源 | 区分信息年龄与决策语义失效；同一 AoI 下不同动作可有不同有效域 |
| Anytime inference | 在截止时间前输出不同质量的预测 | 将中断时刻、物理状态演化与多智能体联合动作兼容性闭环评价 |
| Safety shield/CBF | 对当前状态动作做安全过滤 | 同时处理基于旧快照生成的动作、任务价值保持和异步团队兼容性；shield 只能作为基线 |
| Computation offloading | 决定在哪里运行模型以降低延迟 | 不调度计算资源，而是管理计算完成后决策是否仍有效 |

若最终实现只是 `observation + latency -> action`，本题立即关闭。

## 4. 严格反例要求

训练前必须构造至少两个解析反例：

### 反例 A：相同延迟、不同状态演化

两个轨迹具有相同 \(\tau\)，但一个仍在动作有效域内，另一个已经越界。仅以 delay 为输入的统一接受规则必然在至少一个轨迹上错误；状态—时间有效域可以区分。

### 反例 B：相同旧观测、不同计算完成次序

两个 UAV 从同一联合快照生成互补动作，但随机计算时延使完成顺序不同。无契约的异步执行产生联合动作不兼容；局部契约与冻结的团队兼容规则应触发至少一个回退，并严格降低碰撞或任务违约代价。

反例必须使用相同观察、动作候选、动力学和信息边界，不允许向 DVC 泄漏未来状态。

## 5. 主要受控比较与消融

| 方法 | 时延可见 | 状态—时间有效域 | 回退语义 | 作用 |
|---|---:|---:|---:|---|
| Zero-delay oracle | 不适用 | 否 | 否 | 性能上界，不作公平主对照 |
| Naive asynchronous MAPPO | 否 | 否 | hold-last | 暴露部署失配 |
| Delay-aware MAPPO | 是 | 否 | hold-last | 主要匹配对照 |
| Current-state shield | 是 | 否 | 安全过滤 | 区分通用 shield |
| DVC without learned validity | 是 | 固定阈值 | 是 | 检验学习有效域的作用 |
| DVC-MARL | 是 | 是 | 是 | 完整方法 |

容量匹配规则：DVC 与 delay-aware 主对照共享 actor/critic 骨干和参数预算；多出的 validity head 需要通过等参数辅助 head 或削减隐藏维度匹配。训练预算、时延分布、物理轨迹、随机种子和评价 tape 完全相同。

## 6. 论文指标与证据闭环

### 主要任务端点

- 固定时限内团队任务完成率；
- 任务回报及最差 seed；
- 随机计算负载下相对零时延 oracle 的 performance loss。

### 实时与机制端点

- deadline-miss rate；
- stale-action acceptance rate；
- valid-action rejection rate；
- 契约覆盖率与条件错误率；
- fallback rate 及 fallback 后任务恢复率；
- 团队动作不兼容率；
- 推理延迟分位数 P50/P90/P99，而非只报均值。

### 安全与代价端点

- 碰撞、约束违反和最小间隔；
- 任务收益与安全指标分开报告；
- validity-head 计算开销、峰值内存和控制频率。

训练 seed 是统计单位；每个 seed 内的时延样本和 episode 只用于估计该 seed 的端点，不能扩大独立样本量。

## 7. 训练前阶段门

### P10-A：最近邻非重合门（0 GPU）

必须系统核对 real-time RL、delay-aware control、anytime policy、runtime assurance、action shielding 和 asynchronous MARL。至少证明“学习动作特定状态—时间有效域 + 执行接受语义 + 团队兼容回退”的组合没有直接同构工作。仅有 UAV 应用差异不通过。

### P10-B：解析反例与 oracle 门（0 GPU）

两个严格反例全部通过；枚举 oracle、delay-only、shield 和 DVC 决策。DVC 必须在不使用未来信息的条件下严格减少至少一种错误。

### P10-C：任务可识别性门（0 至极小 GPU）

新环境先冻结再训练。要求：

- zero-delay baseline 可学习；
- naive asynchronous baseline 在中等时延下明显但非全面崩溃；
- 至少 20% 决策点存在动作有效性分叉；
- 固定阈值不能完全解决问题；
- 任务不能靠 always-fallback 获得近最优成绩。

### P10-D：短程资格门

3 seeds、小预算。只有 DVC 在至少 2/3 seed 同时降低 stale acceptance/联合动作不兼容，并保持任务表现不低于 delay-aware baseline 的预设容差，才进入正式实验。

## 8. 质量、成本与风险判断

| 维度 | 当前判断 |
|---|---|
| 科学价值 | 高：直接连接策略推理、实时系统和物理闭环 |
| 新颖性潜力 | 中高：取决于 P10-A 是否存在直接同构工作 |
| 强二区上限 | 有；需要运行时语义、严格反例和真实延迟测量共同成立 |
| 一区上限 | 条件性；需理论覆盖/风险界和硬件在环或真实机载算力证据 |
| 复用程度 | 中低；可复用 MAPPO 与部分 3DOF 动力学，但必须重做异步执行环境 |
| 算力成本 | 中；先解析与小环境门控，正式训练规模后定 |
| 最大风险 | 退化为普通 delay-aware policy 或 safety shield |

## 9. 当前决定

推荐 DVC-MARL 作为 P10 唯一候选，因为它把“算法推理耗时”从论文末尾的运行开销指标提升为会改变最优协同决策的系统变量，并提供可验证的运行时决策对象。

当前仅冻结问题与审查合同，不冻结方法实现。下一步执行 P10-A；若发现直接同构近邻，立即停止，不进入环境和训练。
