# P41 v2 T4：UTR 可学习性计划

## 目的

T1--T3 已证明 P41 v2 有规则层面的动态决策张力；T4 只验证一个更基础的问题：在统一训练暴露下，标准学习策略能否在该任务中获得非随机、非饱和、非全局崩溃的表现。

T4 不是方法效果实验。它不会运行 DRTP、PLR、课程学习、任何自适应分配，也不会产生论文主结果。

## 已冻结的内容

机器可读合同：`configs/p41_v2_utr_learnability_freeze_20260911.json`。

- 三个新训练 seed：`95101--95103`；
- 固定 512 updates、16 个并行环境和 9 步回合；
- 训练、验证、最终带的随机种子和 episode 数相互分离；
- 训练带在三种语义情境族及预警可靠性区间内平衡；
- 最终带在三个 endpoint checkpoint 均存在前保持封存；
- 训练 seed 是唯一独立统计单位。

## 为什么不以“超过最佳规则”作为 T4 门槛

规则策略被用于证明任务结构，不是用来制造一个容易获胜的学习基线。T4 的最低要求是 UTR 超过匹配随机策略、在每类压力条件有非零完成价值、同时至少留有一个压力带低于 oracle。若要求短 pilot 立即胜过每个专家规则，容易把“学习性测试”误变成结果导向的任务调参。

## T4 的四个硬判据

1. 两个以上 seed 在最终带上超过匹配 random-legal 的平均完成服务价值；
2. 两个以上 seed 在每一个压力族获得非零服务价值，且不存在规则与 UTR 同时全零的压力族；
3. 至少一个压力族仍明显低于 audit oracle，排除全局饱和；
4. 每个通过 seed 在合法轨迹中使用两个服务站点并至少一次中继重构，排除学到单一固定行为。

任一失败都输出 `P41_V2_T4_STOP`；不改奖励、不加模块、不增加更新数、不换 seed。

## 实现顺序

1. 生成并哈希三个 scenario tape；
2. 对规则与 random-legal 跑最终 tape，保存同一原始指标；
3. 接入最小 UTR-PPO runner；
4. 完成三 seed 固定 endpoint 训练；
5. 打开最终 tape 并一次性汇总 T4 gate；
6. 仅在 `P41_V2_T4_PASS` 后，回看失败轨迹以决定是否存在值得建模的机制缺口。
