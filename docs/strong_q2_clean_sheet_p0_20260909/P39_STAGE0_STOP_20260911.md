# P39 异步角色跟踪 Stage-0：STOP

## 有效审计版本

V1 的 E4 反事实测量顺序错误，已保留并作废；V2 使用相同环境参数、门槛和种子，只
修复“新鲜缓存”赋值顺序。有效证据为：

- `configs/p39_async_role_tracking_stage0_20260911.json`
- `scripts/p39_async_role_tracking_stage0_audit.py`
- `artifacts/diagnostics/p39_async_role_tracking_stage0_20260911_v2/P39_STAGE0_RESULT.json`

## 结果

缓存时效语义本身成立：相同几何下，新鲜缓存覆盖率为 1.0，过期缓存为 0.0（E4 通过）。
但这不足以产生“何时重构角色”的学习问题：

- 静态分工与最近事件规则均达到 0.90 平均覆盖，触及预设的非饱和上限；
- 一步前瞻选择的切换率为 0，说明当前动力学下维持既有责任不产生需重构的局部决策；
- 匹配几何、改变缓存年龄未改变一步前瞻选择（E2 未通过）；
- 因此无法建立“切换既有代价，也具有不可由固定规则获得的收益”（E3 未通过）。

`one_step_oracle` 的即时覆盖低于静态规则，说明它是一个短视参考，而不是有效的全局
上界；E5 因此不能作为该任务是否有长期规划空间的证据。无论如何，E1--E3 已足以
触发停止规则。

## 决策

`P39_STAGE0_STOP`。不调整速度、范围、缓存时限、黑屏时长、奖励、种子或门槛来让
任务通过；不接入 MAPPO、GRU 或任何候选角色重构方法。

该结果不是“异步观测不重要”的结论，而是当前最小设计中，异步观测没有产生一个超出
静态分工的可识别重构决策。
