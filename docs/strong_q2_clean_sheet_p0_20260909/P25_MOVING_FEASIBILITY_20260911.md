# P25 运动版可行性探针（零训练）

**日期：** 2026-09-11
**脚本：** `scripts/diag_p25_moving_feasibility.py`
**目的：** 在投入 GPU 训练前，确认"单机 + 运动几何"设定下任务可解（P19 round-1 教训：运动/闭环几何可能让任务静默不可解）。

## 改动（向后兼容）

`envs/attitude_coupled_relay_env.py` 新增运动块（默认全 0 = P18/P22 静止语义不变）：
- `agent_speed` / `target_speed`：机头驱动机体、目标移动；指向决定位置，位置又改变指向的目标/中继方位 → 闭环耦合。
- `target_distance` / `relay_distance` / `link_range`：位置与链路距离约束，默认 `link_range=1e9`（纯方向性链路，与 P18 一致）。
- `step` 在运动开启时按当前航向/目标速度更新位置并重算 `target_bearing` / `relay_bearing` / `separation`。

`force_geometry`（P18）同步设置位置，避免运动设定下第一步被位置反推覆盖。

## 探针结果（200 局/设定，随机分离角 10–180°）

| 速度(机/目) | 解析节律表 | 最优固定表 | 可解率 |
|---|---:|---:|---:|
| 0.0 / 0.0 | 28.3 | 26.0 | 74% |
| 0.03 / 0.0 | 20.0 | 19.8 | 68% |
| 0.03 / 0.02 | 19.7 | 19.5 | 68% |
| 0.05 / 0.03 | 13.4 | 13.0 | 62% |
| 0.08 / 0.05 | 8.5 | 9.1 | 58% |

## 两个结论

1. **可行性通过**：运动设定下任务可解，且速度越大越难（28→8.5）。中等速度 **(0.03, 0.02) 给 19.7、68% 可解**，是合适的实验设定。
2. **纠正一个误判**：此前设想"运动让固定时刻表失效、按公式实时算才不可替代" —— **数据不支持**。解析节律表与最优固定表基本打平，高速时固定表略赢。运动的作用是"让固定表无法被预先写死、必须逐帧推导"，而非"推导出来的比表好"。

## 对 P25 设计的影响

主张必须回到 **可学性**：最优排班已知（脚本 ~19–26），但朴素 RL 只拿 5–7（P21），**学不到**。贡献 = "为何学不到 + 给什么结构让它学到"，且运动下结构须逐帧推导。

**P25 门槛（修正版，须训练前冻结）**：
- G1：选项机制 ≥ 1.20× 朴素原动作（机制帮 RL 够到目标）
- G2：选项+推导量输入 ≥ 0.80× 最优固定表（**缩小** RL 与已知优表鸿沟，而非"赢过"——探针已证赢过不现实）
- G3：简单区不退化 ≥ 0.90×
- G4：≥5 种子并逐种子报告

**已撤除的错误门槛**："learned ≥ 1.20× 解析脚本"（探针证伪）。
