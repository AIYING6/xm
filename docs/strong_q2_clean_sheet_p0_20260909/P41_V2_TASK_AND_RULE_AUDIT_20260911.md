# P41 v2：公开预警、不可逆承诺与可恢复服务链

## 状态

`P41_V2_T1_T3_PASS`。该结论仅授权下一步的**小规模 UTR 可学习性检查（T4）**；不授权新方法、多 seed 正式训练、论文主张或对 DRTP 的任何修改。

## 与 v1 的实质差异

v1 的所有服务请求均可被依次完成，因此中继重构只是延迟而非决策成本。v2 同时引入三项语义约束：

1. **公开但不确定的未来服务预警**：所有角色可见未来请求的概率、预计价值、可能释放时刻与截止期；未来请求是否真实发生只由冻结 tape 决定，直至释放后才成为可见请求。
2. **一次不可逆服务承诺**：单次出动只可使用一个服务负载。选择已确认的当前请求会排除等待未来请求的机会。
3. **持续确认链要求**：已承诺服务在完成前需要有效的巡检—中继—服务信息链。中继移动或计划性链路退化会中断当前链，因而重构可恢复但非免费。

该任务属于灾后巡检/应急服务，不涉及目标选择、打击、攻击分配或任何伤害性自治决策。

## T1：信息边界

Actor 可得到：当前已释放请求、公共预测参数、已送达的确认、当前本地中继状态和当前链路退化状态。Actor 不可得到：预测是否会实现、未来请求真值、全局 critic 状态、oracle 动作或最终评价 tape。`envs/recoverable_service_chain_v2_env.py` 中 actor 与 critic 输出分离；冒烟测试通过。

## T2：规则策略交叉

三条冻结场景产生不同的最佳简单规则：

| 场景 | 核心矛盾 | 非特权最佳规则 |
| --- | --- | --- |
| `commit_now` | 高概率预警未实现，等待会损失当前可完成服务 | 静态/最早截止期/拓扑规则并列 |
| `defer_for_value` | 高概率高价值请求实现，立即承诺低价值请求不优 | 价值规则 |
| `reroute_before_outage` | 当前请求价值较高，但公开的即将到来退化会破坏其持续确认链 | 拓扑规则 |

没有单个固定规则在全部情境达到 audit oracle；所有场景至少有一个合法规则可完成非零服务价值。因此该任务没有退化成静态分工，也没有被设计为全局失败。

## T3：恢复的决策后果

规则轨迹中可观测到中继重构和服务中断。由于重构步骤无法传递确认、服务链中断会终止已承诺服务，重构的时机不是装饰性动作；它直接改变完成价值与承诺结果。

## 下一门：T4 小规模 UTR 可学习性

T4 必须在扩展的、预先冻结的 scenario tape 上执行，并在开始前规定：

- 名义和退化场景的构成；
- 训练/验证/最终评价 tape 的严格分离；
- 名义任务最低完成价值、压力场景的非崩溃区间；
- 服务价值、承诺中断、超时/未完成和中继重构的独立端点；
- 若 UTR 不能超过规则下界，或全部策略饱和/崩溃，则永久停止。

在 T4 完成前，不命名、不实现任何新机制。方法只能由学习策略相对规则基线的可重复错误模式推导。
