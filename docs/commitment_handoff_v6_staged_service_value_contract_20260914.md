# V6 阶段服务价值交接任务：开发合同

## V5 后的可证实问题

V5 的 G0 通过，表明四个公开服务信封能够形成相反的可达终局；但冻结 G2 显示普通 MLP 在两类当前画像上全部成功、在未来画像上仅有一个 seed 获得中等成功。只读阶段追踪进一步显示：成功的未来画像轨迹在分支前几乎不重构（约 0.06），而失败轨迹在分支前重构约 0.29--0.30。这不是“没有选择”，而是 V5 的 credit 定义从 episode 起始便奖励未来走廊靠近，与“先维持已授权服务、分支后再重构”的成功执行序列相冲突。

V5 的数据永久保留为开发诊断，不进入候选方法或正式统计。

## V6 的唯一任务修复

保持三架异构 UAV、3DOF 动力学、二元中继宏动作、低层控制、奖励尺度、服务信封、参数量与 actor 信息边界不变。只修改**服务进度在公开任务阶段中的合法目标**：

\[
r_{\mathrm{active}}(t)=
\begin{cases}
\mathrm{current}, & t < t_b,\\
\mathrm{future}, & t \ge t_b \text{ 且 }V_{\mathrm{future}}>V_{\mathrm{current}},\\
\mathrm{current}, & \text{otherwise}.
\end{cases}
\]

其中 \(t_b\) 是公开任务分支；actor 获得归一化的公开分支进度标量，除此以外不加入 profile one-hot、目标真值或未来机动信息。当前服务与未来服务的最终价值仍仅由公开信封 \((\tau,a,h)\) 的固定关系定义。

因此未来服务画像的正确策略不再是“始终重构”，而是**分支前保留、分支后重构**；并且早期授权缺失不能由后续刷新追溯补救。当前画像保持保留。V6 解决的是已实测到的错误 credit-path，而不是调节网络、采样器或 G2 阈值。

## 重启门禁

在训练前进行的有界零训练几何校准（3 个物理 seed、未来画像）表明：在候选 branch \(32,36,40\) 与横向偏移 \(900,1100,1300,1500\) 中，只有偏移 900 同时具有非零后续刷新成功（两画像均为 2/3）和完整早期授权；偏移不小于 1100 均因碰撞导致后续刷新为零。按预先声明的“最大化两画像最小成功率、再保留较晚分支”的规则，冻结 \(t_b=40,\Delta y=900\)。

1. 新 G0：对每个 profile、六个物理 seed，比较 `always_retain`、`always_reconstruct` 与 public-stage-aware 控制器。当前画像必须由保留控制成功；未来画像必须由分支前保留、分支后重构的控制成功，且两种非阶段对照不得替代它。
2. 新 G2：仅在 G0 通过后，重新冻结 3 个新训练 seed、预算、端点评估带和中等成功判据。不得复用 V5 的训练 seed 或把 V5 结果并入 V6。
3. 仅 G2 通过后才实现服务关系价值候选机制与语义打乱消融。

V6 仍是开发任务，尚无论文结果或候选方法性能主张。

## 已冻结的首次 V6 G2 合同

- 训练 seed：`83441, 83442, 83443`；每 seed 64 updates、4 个并行环境、每 rollout 64 个宏决策；
- 固定任务：`compositional_v6_staged`、公开 branch `40`、未来走廊偏移 `900`、其余 V6 G0 合同不变；
- 固定 endpoint：每 seed × profile 60 回合，未参与训练的固定评价 seed 带；
- 通过条件：每个未来-required profile 至少 2/3 seed 的成功率位于 `[0.10,0.90]`；所有当前-required profile 必须有非零成功；未来画像上 postbranch 的平均重构比例比 prebranch 至少高 `0.15`。

当前画像的高成功不是 V6 的饱和失败，因为其公开任务仅要求维持当前桥；非饱和性与阶段学习压力由两个必须完成“授权再刷新”的未来画像评估。阈值和预算在本次训练启动前固定。

## 首次 V6 G2 之后的基线稳定化修复（开发用）

首次冻结 V6 G2（`83441--83443`）未通过，原因不是阶段任务缺乏可识别的选择：三 seed 合并的未来画像中，分支后重构比例相对分支前提高 `0.181`，超过预设的 `0.15` 条件。失败来自两个训练 seed 的**二元 relay 宏动作塌缩**：它们在四个 profile 上均以重构动作为主（端点重构比例 `1.0`），并同时在当前画像也出现碰撞/超时，从而不能作为“基线已学会、但未来服务仍有改进空间”的有效对照。

为修复该已测得的优化失败，V6.1 只作一个受控的基线稳定化改变：将 relay-only PPO 的熵系数由 `0.01` 提升为 `0.03`。保持环境动力学、服务信封、公开观测、二元动作、网络宽度、PPO 目标、rollout 规模、训练 update 数、评价带和 G2 通过条件完全相同；不改变候选机制，也不将 V6.1 当作方法比较结果。该改变直接针对“过早失去二元动作探索”的日志证据，而非通过放宽门槛或改变任务来追求通过。

V6.1 将使用新的一组 3 个开发 seed。只有在同一 G2 审计下通过后，才允许实现候选关系价值机制；V6 与 V6.1 均永久保留为开发性学习门禁，不能用于论文统计。

## V6.2：针对残留的错误初始承诺

V6.1 保留了阶段行为（未来 profile 的 postbranch--prebranch 重构差为 `0.347`），但仍有一个 seed 在所有四个 profile、所有阶段均选择重构，因而当前服务也以碰撞/超时失败。该模式与未来路线的难度无关：它违反了 G0 已验证的公共结构——在 branch 之前，四个 profile 均应保留当前服务。

V6.2 采用一次且仅一次的、与任务公共语义一致的初始化修复：在二元 commitment policy 的初始 logits 中加入对 action 0（retain-current）`+0.25`、对 action 1（reconstruct-future）`-0.25` 的对称偏置，并维持 V6.1 的熵系数 `0.03`。该先验不随 profile、目标状态、通信内容或测试样本改变；它不改变观测、参数量、环境、奖励、PPO 更新、训练预算或 endpoint，也不决定 branch 后的动作。其唯一作用是在每个 profile 均正确的早期阶段避免随机初始化直接选择具有物理碰撞代价的重构。

V6.2 将使用新的独立三 seed 开发队列，并沿用完全相同的 G2 通过条件。若它仍不能建立稳定的普通 MAPPO 基线，则不会继续提高先验或扫描系数；届时将把问题定位为当前二元宏动作接口本身的可学习性不足，而非候选关系价值机制的缺失。

## V7：两次因果承诺接口（V6.2 后的结构性修复）

V6.2 的独立开发队列 `83641--83643` 未通过 G2：仅 `83641` 在未来画像达到中等成功；`83642` 与 `83643` 在所有画像、所有阶段均选择重构。虽然合并的分支后重构比例高于分支前比例（`0.243`），但该统计由一个成功 seed 与两个全局塌缩 seed 混合而成，不能证明普通基线已经可稳定学习。因此不再继续搜索初始化偏置或熵系数。

V7 改变的不是奖励、观测、网络或候选机制，而是**高层动作的因果接口**。旧接口要求策略在每个 8 个物理步的 option 边界重复采样相同二元宏动作，其中绝大多数采样不会改变已建立的服务状态，造成二元策略的全局塌缩。V7 只在两个公开、可审计时点令 relay 的动作进入状态转移：

1. `t=0` 的授权承诺：选择 `retain` 才能保留当前服务的合法授权资格；
2. `t=24` 的公开分支承诺：未来服务画像必须选择 `reconstruct` 才能取得后续刷新资格。

两次以外的 placeholder 不进入 relay 的 PPO likelihood 或 entropy 项；该掩码只由公开任务时钟决定，不是 actor/critic 输入，也不使用 profile 标签、目标真值或未来机动。高层服务任务保留 blue-team 队形碰撞与边界约束为终止安全条件；红方接触仍记录，但不再用固定低层 target tracker 的无关接触终止服务决策回合。

在六个独立零训练物理 seed 上，V7 G0 以 `Δy=900`、`t_b=24` 验证：当前画像 `always_retain=1.0` 且 `always_reconstruct=0.0`；两个未来画像仅 `retain-then-reconstruct` 规则成功（均为 `1.0`），两种始终策略均为 `0.0`。因此 V7 建立了可由公开时钟与服务承诺解释的相反最优终局，但仍仅是开发性任务地基，尚不构成候选机制或论文证据。

V7 G2 冻结合同见 `configs/commitment_handoff_v7_g2_freeze_20260914.json`：新三 seed 的普通 MLP MAPPO 必须在两个未来画像各有至少 2/3 seed 的端点成功率落于 `[0.10, 0.90]`，同时在至少 2/3 seed 保留早期授权并在分支后重构。只有该门通过，才允许设计关系价值候选机制及其语义打乱消融。
