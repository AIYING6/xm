# PSCR-v3：双出口延迟选择拦截任务合同

**状态：`ZERO_TRAINING_ONLY`。** 本文件冻结一个新的任务地基，用于回答“是否存在足以识别协同决策机制的物理冲突”；它不冻结算法、也不授权训练或论文主张。

## 为什么重构

P8/P9/P10 的服务链承诺变体未能稳定改变最优选择：提前承诺、容量释放与后续服务之间没有形成可识别的决策翻转。因此它们不能通过继续调参获得机制证据。PSCR-v3 不修改旧环境、不复用旧结果，而把冲突移至原生飞行几何。

## 任务

三个异构蓝方 UAV 保留现有 27 个离散 3DOF 原始动作（转向、爬升、加速度）。红方先沿公开接近轨迹飞行；第 42 步时，根据已经形成的蓝方空间覆盖，选择两个物理逃逸出口中覆盖较弱的一侧，并以其既有最大速度驶向出口。蓝方需要在接近、分散覆盖与保持可形成攻击窗口的协同之间作取舍。红方到达出口则逃逸；蓝方只有在既有的感知、通信和攻击窗口链闭合时才成功。

该选择不是隐藏标签：选择之前不存在出口真值；选择之后，信息仅通过红方真实运动与既有合法观测传播。Actor 和 critic 均不接收未来出口标签。

## 唯一允许的后续顺序

1. **G0（当前）**：接口、无泄漏、延迟选择、出口物理终止的 smoke test。
2. **G1**：零训练控制器审计。只有“集中追击、双出口分置、延迟保持”存在非退化胜出区域，才说明任务中存在真正的选择冲突。
3. **G2**：短预算 plain MAPPO 可学习且不饱和。
4. 仅当 G0–G2 都通过时，才可以提出并冻结新方法、对照和消融。

## G1 的上下文格点（v2 审计）

第一轮 G1 发现同一初始几何被重复采样，集中追击在全部单元获胜；这不是可识别的选择冲突。因而 v2 仅增加四个预注册的物理初始上下文：居中接近、正/负侧接近、以及宽初始编队。它们保持动作、奖励、动力学、分支规则与评价终点不变。G1 要求至少两类透明原始飞行控制器在不同单元成为唯一的终端目标最优策略；否则不进入学习实验。

第二轮格点审计仍显示集中追击在全部单元的终端目标排序中获胜。这表明问题不是采样不足，而是当前继承的“攻击窗口链闭合即成功”终点允许红方在出口选择之前被截获。不得通过事后设置人为最小成功步数来掩盖该事实；该任务版本不获准进入 G2。

## 禁止事项

- 不把 P8/P9/P10、P3B 或旧 PSCR 的数据写成 PSCR-v3 结果。
- 不把宏意图、规则控制器或红方覆盖规则包装为算法创新。
- 不在 G1/G2 前训练候选方法或开启云端长训练。
- 不声称该环境已经支持强二区论文；现在只是在建立它是否值得投入的可检验地基。
