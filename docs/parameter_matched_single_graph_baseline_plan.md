# Parameter-Matched Single-Graph Baseline Plan

Last updated: 2026-07-22

## Purpose

The current main comparison includes a standard single-graph baseline with hidden dimension `128`. Its parameter count is much smaller than the full multi-relation model, so a reviewer could argue that the advantage partly comes from model capacity.

To address this, add a parameter-matched single-graph baseline:

```text
Single-graph MAPPO (param-matched)
graph_encoder = single
hidden_dim = 240
role_dim = 8
intent_dim = 8
```

This preserves the single union-graph information structure while increasing network capacity.

The parameter-matched single-graph baseline has `1.2%` more total parameters than the full method.

## Experimental Status

Not trained yet.

The current result is a capacity-control plan and model-cost artifact update, not a performance result.

## Recommended Execution

Use a staged approach before any full five-seed formal run:

1. Smoke:
   - seed `0`;
   - small strict-sensing continuation;
   - verify training stability and checkpoint loading.

2. Development diagnostic:
   - seeds `0, 1, 2`;
   - fixed `update_0060`;
   - evaluate `dropout030_relay_failure`;
   - compare only against the existing full fixed-update-60 reference on a small matched budget.

3. Formal promotion:
   - seeds `0, 1, 2, 3, 4`;
   - same frozen fixed-update-60 test protocol;
   - 100 matched test episodes per seed;
   - seed-aware full-minus-param-matched-single bootstrap.

## Boundary

This baseline tests whether full-method gains survive a same-capacity single-graph comparison.

It does not test relation-channel causality by itself. Relation causality remains supported by `no_task_support` and `no_role_pair_gate` ablations.
