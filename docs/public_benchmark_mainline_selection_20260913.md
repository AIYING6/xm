# 公开基准主线：基准接入前的机制选择卡

**日期：** 2026-09-13  
**阶段：** `CLOSED_BY_RESEARCH_SCOPE_20260913 / NO TRAINING`
**目的：** 停止在自建 UAV 场景中连续改写任务，再从成熟合作 MARL 基准中寻找一个可被受控比较验证的算法问题。UAV 连续控制环境只在主机制成立后作为应用外推，不再单独承担算法有效性的全部证据。

## 1. 已核验事实

1. 当前 `cac` 环境可导入 `lbforaging`，但不能导入 `smac`、`smacv2` 或 `pettingzoo`。因此仓库没有可直接复用的 SMAC/SMACv2 正式实验；后续任何公开基准结果必须从可追溯的依赖安装、接口适配和冻结协议开始。
2. LBF 曾通过信息价值和基线可学性检查，但“未知/演化队友能力推断—重分配”与既有异构机器人能力分配工作直接相邻，已被停止；不得以更换网络或增加 UAV 应用重启。见 `docs/strong_q2_clean_sheet_p0_20260909/C1_LATENT_CAPABILITY_TEAMING_RESEARCH_CONTRACT_20260911.md`。
3. 反事实团队信用不能作为新的主方法族：COMA 已使用在保持其他智能体动作固定时边缘化单个智能体动作的反事实基线；Shapley counterfactual credit 已直接研究合作 MARL 的反事实信用。将其改名为“可行联盟信用”“阶段信用”或接到 DRTP 上，均不足以形成可辨别的强主张。
4. 旧的公开多 UAV 任务分配候选不具备任务执行过程中的事件、进度与可区分的承诺/释放语义，不能作为时间承诺算法的主证据。见 `docs/strong_q2_clean_sheet_p0_20260909/PUBLIC_BENCHMARK_SINGLE_CANDIDATE_G0_G3_STOP_20260911.md`。

## 2. 本轮唯一允许接入的公开证据平台

**SMACv2** 被暂定为主证据平台，不是因为它自动提供创新，而是因为它是公开、持续维护的合作 MARL 基准，并包含 CTDE 下的异质单位协作和场景随机化。其官方实现与论文入口为：

- https://github.com/oxwhirl/smacv2
- https://arxiv.org/abs/2212.07489

本地零训练源码审计已固定官方仓库 `oxwhirl/smacv2` 的浅克隆提交
`577ab5a2cff2391f8df582da5731ea9cd6adf3c6`（`third_party/smacv2/`，不作为本项目维护源码提交）。该版本提供 `reset`、`step`、`get_obs`、`get_state`、`get_avail_actions` 与 `get_env_info` 接口，因而可以在不改变 SMACv2 动力学或奖励语义的前提下接入本仓库 adapter。其运行依赖还包括 PySC2、StarCraft II 客户端和官方地图文件；当前 Python 依赖下载被本机 TLS 证书链错误阻塞，完整状态见 `docs/smacv2_admission_audit_20260913.md`。在这些依赖被验证前，不得报告基准运行或比较结果。

接入 SMACv2 只授权回答三个工程—科学前提：

1. 是否能在不改变基准语义的情况下映射到仓库的标准 `reset/step` 接口；
2. 容量匹配 MAPPO 是否在冻结的小场景带中可学习且不全面饱和；
3. 是否存在一个**不是一般信用分配、belief 推断、普通通信、对手分类或任务重分配换名**的、可枚举的决策失败现象。

这三项均不是性能论文结果。它们只决定是否值得冻结一个新算法问题。

## 3. 已排除与待寻找的边界

### 已排除的主机制

| 机制族 | 排除原因 | 证据入口 |
|---|---|---|
| 训练样本/故障组重加权 | DRTP 已完成；继续修改采样器难以构成独立算法问题 | `docs/DRTP_FORMAL_MAINLINE_STATUS_20260911.md` |
| 个体动作反事实信用、差分回报、Shapley 信用 | 与 COMA、difference-reward、Shapley credit 的核心对象重合 | `configs/cv_drtp_d0_design_freeze.json`；`docs/strong_q2_clean_sheet_p0_20260909/P5A_Q1_IDENTIFIABILITY_AND_STOP_DECISION_20260910.md` |
| 未知队友能力 posterior | 直接邻接现有异构团队在线能力分配 | C1 合同 |
| 对手 embedding/策略库选择 | 已被 CIRU/OSTA 审计为高重合，且旧任务缺少稳定响应专门化 | `docs/strong_q2_clean_sheet_p0_20260909/P6_CIRU_FINAL_CLOSURE_20260910.md` |

### 待寻找的最小资格对象

后续算法问题必须明确给出一个**轨迹级而非单动作级**的协作决策对象，并同时满足：

1. 同一局部信息下至少两种联合执行策略在后续可观测结果、协调代价或可行性上严格分叉；
2. 强记忆 MAPPO、普通集中 critic、COMA 型单动作信用与静态角色/通信参考都不能等价实现该对象；
3. 方法的唯一干预、主对照、至少两个消融、机制端点、失败边界和训练 seed 的统计单位能在训练前写成合同；
4. 该对象能先在 SMACv2 的公开场景带上验证，再考虑 UAV 应用外推。

在这四项之前，**不得命名新算法、不得租卡、不得写“强二区”结论，也不得把 DRTP 历史结果并入新线。**

## 4. 单次执行顺序

1. **基准接入审计（零训练）：** 安装固定版本的 SMACv2，记录版本、许可证、SC2 依赖、观察/动作/全局状态接口和随机化来源；建立不改变语义的 adapter 与 smoke test。
2. **可学习性审计（短预算）：** 仅运行容量冻结的 MAPPO baseline，报告训练曲线、胜率、动作合法性、场景难度分层和是否饱和。
3. **现象筛选（零训练/冻结策略）：** 以跨场景 rollout 或可枚举微状态寻找上述“轨迹级协作决策分叉”；没有分叉即停止，不能靠添加人为奖励或隐藏标签制造。
4. **机制合同：** 仅在步骤 1--3 通过后，做一次最近邻文献矩阵和方法—对照—消融—指标的冻结；随后才授权最小方法 pilot。

## 5. 当前结论

当前不是“已找到算法题目”，而是已经把错误路线压缩掉：公开基准可作为可信的主证据底座，**但反事实信用不是可用的新题目**。下一步是接入 SMACv2 并审计是否存在值得解释的轨迹级协作失败现象；如果没有，就以该结果关闭这一候选，不再在同一基准上连续改名试错。

### 2026-09-13 范围关闭更新

研究者决定不引入 StarCraft II 游戏引擎作为本项目运行时，因此 SMACv2 不再是本项目的公开基准主线。该关闭发生在任何 SMACv2 adapter、baseline、DER 或正式训练之前；不存在可报告的 SMACv2 性能结论。`third_party/smacv2/`、已安装 Python 包和 Battle.net 客户端均不构成论文资产或维护中的实验链。
