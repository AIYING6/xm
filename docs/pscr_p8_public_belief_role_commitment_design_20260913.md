# P8：公共信念驱动的角色承诺（PBRC）受控方法设计

**状态：** 仅限实现前设计；尚无 PBRC 训练或性能结论。

## 1. 由已冻结开发证据推出的缺口

P8 的零训练计划审计表明，高可靠度预测下 Scout--Relay 前置部署优于维持，而低可靠度下方向相反。最小 plain-MAPPO 门则表明，任务可学习且不饱和；但固定端点行为审计显示，plain MAPPO 没有在两条可靠度带之间改变承诺窗口中的成组角色分配。

这只支持一个有限问题：**独立角色动作的策略表示是否难以将公开信念转化为可执行、持续的团队承诺？** 它不支持“普通 MAPPO 无法完成 P8”，也不支持任何新方法已经更优。

## 2. 候选干预：PBRC-MAPPO

PBRC 的 actor 在公开承诺窗口输出一个团队级二元计划：

- `maintain`：三角色维持当前服务；
- `forecast_stage`：Scout 与 Relay 进入公开预测扇区，Executor 保持当前服务。

计划仅由所有 actor 已合法获得的公共变量（预测扇区、可靠度、到达剩余时间、当前服务状态）和各角色局部状态产生。选择后在既有公开锁定窗口内映射为三条确定的角色意图；请求激活后，策略恢复既有公共的逐角色服务意图。PBRC 不读取激活前未来真值，不改 3DOF 动力学、奖励、通信图、任务截止或训练暴露分布。

方法假设是结构性的：将团队级、不可逆的公共承诺显式化，能够降低独立角色动作在“同一时刻需要形成互补分工”时的协调组合难度。它不是采样重加权、额外奖励或隐藏信息恢复方法。

## 3. 必须受控的比较与消融

| Arm | 团队计划接口 | 使用公开可靠度 | 承诺锁定 | 识别问题 |
|---|---:|---:|---:|---|
| Plain MAPPO | 否，独立角色意图 | 是 | 环境已有 | 基础可学习性与非结构化对照 |
| Plan-MAPPO | 是 | 否（可靠度置为常数） | 是 | 团队计划接口本身是否足够 |
| PBRC-MAPPO | 是 | 是 | 是 | 公开信念条件化的完整干预 |
| Permuted-PBRC | 是 | 置换 0.1/0.9 语义 | 是 | 收益是否依赖正确的可靠度语义 |

除上述 actor 输出结构和可靠度处理外，各 arm 必须匹配：训练 seed、PPO 更新、参数预算、环境、观察维度（用无信息占位保证维度匹配）、奖励、终点和评估带。

## 4. 小规模进入门（先于正式训练）

PBRC 只可先运行 3 seed 开发门，且必须同时满足：

1. 不出现全局任务失败或双带完成率饱和；
2. PBRC 在高/低可靠度带的阶段计划频率出现预定义方向差异；
3. 该差异不能仅来自激活后未来任务动作；必须在未来请求激活前的锁定窗口出现；
4. Plan-MAPPO 与 Permuted-PBRC 均保留相同接口或容量，避免把计划空间变化误写成可靠度语义收益；
5. 安全、能耗、当前任务完成与未来任务完成分列，不能用单一回报掩盖代价。

若上述任一项失败，则停止 PBRC 线，不进入 5 seed/长预算正式比较。

## 5. 证据边界

即使开发门通过，PBRC 也只能被解释为：在此冻结 P8 任务内，公共信念条件化的团队承诺可能改善角色协同。它不能直接推出真实飞行有效、一般性多 UAV 优越、最优性保证或跨任务泛化。
