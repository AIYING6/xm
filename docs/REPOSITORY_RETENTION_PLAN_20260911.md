# 仓库证据与历史资产保留计划（草案）

## 当前原则

本计划先定义保留范围，不执行删除。任何位于 `results/`、`artifacts/`、根目录压缩包、外部下载目录或历史论文目录中的文件，在被确认归类前均保持原样。

## A. 必须保留：DRTP 论文证据链

1. 最终 A/B cohort、固定端点评估、OOD、PLR、有效机制分析、统计汇总和对应原始 archive；
2. 与这些结果一一对应的冻结合同、训练/评估/汇总脚本、seed registry、SHA256 清单和论文图表源；
3. 最终中文主稿及其可编辑源、引用库和审计记录；
4. 对正式结论产生解释边界的少量历史反向/失败诊断，但仅保留其最终报告与 provenance，不保留重复训练包。

## B. 必须保留：可复用工程资产

- `envs/` 中的标准环境接口和 3DOF UAV 环境；
- `algorithms/` 中 MAPPO、图编码器与 EA-RG-MAPPO 核心实现；
- 现役 `configs/`、训练/评估/统计/复现脚本；
- EA-RG-MAPPO Q2 线的冻结协议、baseline identity audit、模型成本与正式评估脚本。

## C. 应迁入 archival：历史可追溯但不作为现役证据

- 已停止候选（P3B、P6、P6R、A0 等）的最终合同与最终审计报告；
- 旧 2D、旧 3DOF、旧 EGTR/GA/稳定化分支中对“为何不纳入当前论文”有说明价值的最终报告；
- 各类云端 package 的最新有效版本及其 SHA256，前提是可追溯到一个保留的最终报告。

## D. 删除候选（须经下一轮逐文件核验）

- 同一实验的重复云端包、修复包、重复 `.sha256`；
- 已被更高版本替换的一次性 preflight、eval-fix 与 cloud-launch 包；
- 无正式结果、无最终报告、无代码依赖的失败候选 package；
- `*.tmp`、PDF 页面渲染缓存、重复渲染输出、临时诊断目录；
- 中断且未完成、又无法用于 bug/provenance 解释的训练输出。

## 盘点发现（初步）

- 根目录直接文件约 1.21 GB，最大的部分是历史云端训练包与多次修复包；
- `results/canonical_v2/formal/wave1/` 是未完成的 EA-RG-MAPPO 训练，必须标为开发/中断资产，不能作为正式论文证据；
- 工作区存在大量用户既有未提交修改与未跟踪文件；本计划不得覆盖、删除或自动 stage 它们；
- 当前仓库中的正式 DRTP 证据需要先通过“结果 archive → 合同 → 汇总 → 图表”反向链接核验，再决定每个原始包是否保留。

## 下一步

建立机器可读的 `retention_manifest`：对候选文件按 `keep_active / keep_archive / delete_candidate / unresolved` 四类登记路径、哈希、理由、来源报告和依赖关系。完成后先给出数量、体积和逐组列表，再申请删除授权。
